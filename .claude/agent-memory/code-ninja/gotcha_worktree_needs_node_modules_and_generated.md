A `git worktree add` of this repo cannot run the test suite until you symlink two
gitignored directories from the main checkout:

```
ln -s /path/to/lms/node_modules node_modules
ln -s /path/to/lms/generated    generated
```

**Why:** `npx vitest` without `node_modules` resolves vitest from the npx cache and
dies at startup on `Cannot find package 'vite'`. Worse, once node_modules is
linked, 26 suites fail with

> [vitest] There was an error when mocking a module. If you are using "vi.mock"
> factory, make sure there are no top level variables inside…

which blames your `vi.mock` call and is a complete red herring. The real cause is
four lines down: `Failed to resolve import "@/generated/prisma/client" from
"db/index.ts"`. `vitest.config.mts` aliases `@/generated` to
`path.resolve(__dirname, './generated')` — the **repo root**, not `src/` — and
`/generated/prisma` is gitignored, so a worktree has no copy. See
[[project_vitest_generated_alias]].

**How to apply:** do both symlinks as the first thing after `git worktree add`,
before running any test or typecheck. `node_modules` is gitignored so it stays
invisible to git; `generated` is only ignored as `/generated/prisma`, so the
symlink itself shows up as untracked — never `git add -A` in a worktree, stage
your files explicitly. A per-worktree `info/exclude` does NOT work: git reads
only `$GIT_COMMON_DIR/info/exclude`.

**The symlinked node_modules can be stale.** The main checkout installs for
whatever it last had checked out; once origin/dev carries a dependabot bump the
link type-checks your branch against old packages. 2026-10-05: `tsc` failed in
an untouched `src/lib/email.ts` (`Property 'group' does not exist on type
'Address'`, nodemailer types) until a real `npm ci --allow-remote=all` in the
worktree (~1-2 min, run it in the background). If a typecheck error lands in a
file you did not touch, suspect this before the code.

Worktrees are the right answer when several agents share this checkout —
branch-switching in the shared tree corrupts everyone else's work in progress.
