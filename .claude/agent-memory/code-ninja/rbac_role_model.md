RBAC model (current as of 2026-09-21; originally rolled out on the `rbac` branch):

- **DB enum `UserRole`** (snake_case, `prisma/auth.prisma`), **14 values**. Six **manager**-category roles: `owner`, `admin`, `supervisor`, `hr`, `clinical_director`, `finance`. Eight **worker**-category roles (all sharing ONE identical permission ceiling — they differ only by category + display name): `psychiatrist_prescriber`, `nurse`, `therapist_clinician`, `case_manager`, `behavioral_health_technician`, `peer_support_specialist`, `front_desk_admin`, `facilities_support`. The single old `worker` role is gone. `admin` is a live, delegated Owner-equivalent seat — NOT the retired legacy `admin` (see [[gotcha_admin_role_unretired]]). Neither `users.role` nor `invites.role` carries a DB DEFAULT — every create must pass an explicit role.
- **`src/lib/rbac/permissions.ts`** is the authoritative permission registry. `Role` has a `category: 'manager' | 'worker'` field. The 8 worker roles reuse a single shared `const workerPermissions` array (defined once — never duplicate the literal 8×). RoleKeys are camelCase (`clinical_director→clinicalDirector`, `front_desk_admin→frontDeskAdmin`). `owner` and `admin` = full `everything`; `supervisor` is **read-only** (read on every resource except billing, no write verbs — its power is facility SCOPE, not verbs). So `billing.*` holders = **owner, admin, finance**.
- **`src/lib/rbac/role-utils.ts`** is the ONLY place snake↔camel conversion happens (`dbRoleToRoleKey`, exhaustive `DB_ROLE_TO_ROLE_KEY`), plus `ADMIN_ROLES`/`WORKER_ROLES`/`ALL_ROLES` (typed `readonly Role[]`; spread as `{ in: [...WORKER_ROLES] }` in Prisma filters), `GRANTABLE_ROLES`, the actor-role lists (see [[gotcha_rbac_actor_lists_vs_permissions]]), `getRoleDisplayName`, and predicates `isAdminRole`/`isWorkerRole`. Client-safe. Also exports **`DEFAULT_SELF_SERVE_WORKER_ROLE = 'front_desk_admin'`** — the fallback worker role used wherever the system must create a worker without an explicit category (self-signup, OAuth-no-invite, invalid-invite-role fallbacks, join-by-code, onboarding invites, course-assignment auto-create, CSV import non-admin). Low-stakes label (all worker roles share perms). NOTE: CSV import still uses the legacy token `'admin'` to mean "a manager" and maps it to `supervisor` with a literal check (`src/lib/enrollment/create.ts`: `entry.role === 'admin' ? 'supervisor' : …`) — now that `admin` is also a real DB role, don't route that token through `isAdminRole`.
- **`src/lib/rbac/authorize.ts`** — `authorize(permission)` route guard returning `{ ok, ctx }` or `{ ok:false, response }`. `src/lib/rbac/require-permission.ts` is the page-level equivalent (see [[gotcha_q26_deny_shape_traps]]).

**Grants (`GRANTABLE_ROLES`):** `owner` is NON-grantable (absent from every list; established at org creation). Owner may grant admin, supervisor, hr, clinical_director, finance + all 8 worker roles. Admin may grant the same minus `admin` (only an Owner delegates Owner-equivalent access). HR may grant everything except `admin` and `owner` (founder Q10). Supervisor, clinical_director, finance and all worker roles grant nothing. New org founder (OAuth-no-invite, credentials onboarding, org creation) becomes `owner`. `InviteStaffModal` sources its role options from `GRANTABLE_ROLES[inviterRole]` + `getRoleDisplayName`.

**Seats — unresolved:** the code currently counts plan seats two ways (`src/lib/seat-limits.ts` excludes the owner; the billing overview route includes everyone active). Tracked as **BUG-07** / **Q-11** in `docs/local/OPEN-ISSUES.md` — don't treat either as the rule. See [[billing-schedule-deferred-scope]].

The legacy `'admin'|'worker'` binary is a SEPARATE routing/portal concept, not an RBAC enum value — see [[auth-instance-vs-role]].
