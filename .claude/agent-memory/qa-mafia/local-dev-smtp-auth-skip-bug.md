**Confirmed 2026-07-24 on local dev (`next dev`, `.env`'s `SMTP_HOST=smtp.zoho.com`, real `SMTP_USER`/`SMTP_PASSWORD`).** `src/lib/email.ts` computes `const isDevelopment = process.env.NODE_ENV === 'development'; const skipSmtpHardening = isDevelopment || isLoopbackSmtpSink;` then builds the nodemailer transporter with `auth: skipSmtpHardening ? undefined : { user, pass }`. Because `next dev` always sets `NODE_ENV=development`, this drops SMTP auth **even when the configured host is a real, non-loopback remote SMTP server** (Zoho), not just for loopback sinks like MailHog as the code's own comment intends. Every single email kind sent in a `next dev` session against Zoho fails identically with `Mail command failed: 530 5.5.1 Authentication Required.` — confirmed for `course_invite`, `course_launch`, `staff_removed`, and `staff_removal_confirmation` kinds in one run. The app degrades safely (`email_messages.status='failed'`, no crash, no false-positive success UI), so this never blocks a *feature* test, but it means **no email ever actually leaves a `next dev` session in this repo**, regardless of which SMTP host is configured in `.env`.

**How to apply for future QA runs:** don't waste time chasing "did the invite arrive in the QA Gmail inbox" when running against local `next dev` with the real Zoho SMTP config — it structurally cannot succeed. Instead: (1) confirm the correct email `kind` fired via the `email_messages` table (`SELECT to_email, kind, status, last_error FROM email_messages WHERE to_email=...`) to prove the right code path executed, and (2) fetch the invite/reset/verification token straight from the relevant table (`invites.token`, `verification_tokens.token`, etc.) to continue the journey, exactly like the project's own Playwright e2e specs do (see `tests/e2e/assign-course-invite.spec.ts`, `remove-reinvite-clean-slate.spec.ts`). Report the transport reality explicitly rather than assuming MailHog is in play — MailHog is present in this environment (`http://localhost:8025`) but is **not** the wired SMTP host (`.env`'s `SMTP_HOST` points at Zoho, not `localhost:1025`), so it will show nothing for this app's outbound mail unless `SMTP_HOST` is explicitly overridden to `localhost`/`127.0.0.1` in `.env.local` (which would then hit `isLoopbackSmtpSink` and skip hardening correctly).

**Not a product bug worth filing against a feature PR** — it's a pre-existing, dev-only transport-hardening gap unrelated to whatever feature you're testing. Worth a one-line mention in any report where real email delivery couldn't be confirmed, but don't let it block validating the rest of an invite/email-triggering flow via `email_messages` + DB tokens.
