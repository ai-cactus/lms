**Two "critical new defects" reported this round, both since RESOLVED:**

Export polling has since moved onto `useJobStatus` (#642). If a download seems not to fire, check the download handling in the playwright session before reporting it.

**CONFIRMED — draft-course state is genuinely unreachable via ANY org-facing UI in this product, matching the fix's own PR description verbatim** ("The creation wizard's Step 7 never hands a draft to an assign action. It either creates the course published... or parks `Course.pendingAssignment`"). Live-proven twice: canceling the wizard's final "Confirm Course Review" dialog (instead of clicking Publish) leaves the Reading Course tab count completely unchanged — **no Course row is created in the DB at all** until the final Publish click, which publishes atomically. Exiting mid-wizard shows an accurate "unsaved progress will be lost" warning. This blocks BOTH Story 3's draft-exclusion-from-audit criterion and Story 4's draft-assignment criterion at the root — there is no live fixture to test against without either (a) a document engineered to trigger the AI quality-gate hold, or (b) direct DB access to raw-insert a `status: draft` row (which is literally how the project's own e2e suite does it, per pr-drafts.md: "`course-publish-review-gate` is the only spec that raw-SQL-inserts a real draft course"). Positive control: completing the wizard's own publish-and-assign flow (Step 7, role-target selection) produced a real published course + real enrollment with zero orphan-draft risk observed, on both D01 and B4.

**Course-creation wizard mechanics learned this round, useful for any future course-creation task on this app:**
- The wizard has a client-side "Resume your draft?" dialog (session-scoped, DIFFERENT concept from `Course.status: draft`) that reliably resumes an abandoned generation WITHOUT re-running the AI pipeline — huge time-saver if a prior session's generation completed but you clicked away before finishing Step 7. Confirmed working across both a same-tab abandonment and a fresh page load.
- **Do NOT click "Go to Dashboard" from the "Your course is being created..." screen** — that abandons the wizard before the course is ever persisted. The generation itself (steps 1-4) only produces a resumable session state; the actual `Course` DB row is created (already published) only at the very last "Confirm Course Review" → Publish click in Step 7. This cost significant time to diagnose — I initially mistook the resulting empty course-list for a "course generation silently fails" bug before discovering the resume mechanism proved otherwise.
- Step 7 ("Assigning & Publish") requires picking at least one assign target (Individual Email Invite or Select by Roles) before "Publish Course" enables — there is no "skip assignment, just save as draft" affordance anywhere in the wizard.
