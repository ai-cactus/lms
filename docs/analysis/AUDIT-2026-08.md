## The dominant pattern

Three of the most serious findings below share one shape: **`@deprecated` or internal-helper code inside a `'use server'` module.**

In Next.js, every exported async function in a `'use server'` file is a live HTTP endpoint whose action ID ships in the client bundle. A caller does not need to go through the UI. Meanwhile `@deprecated` and "internal helper" both read as *not a concern* during review, and "exported only for testing" reads as *harmless*.

The consequence: `analyzeDocument` escaped **three separate remediations** (F-012 shared session guard, F-017 upload size cap, F-018 AI rate limits). Each of those findings was genuinely fixed — on the paths the auditor examined. The class was never swept.

**Rule going forward:** when verifying a closed finding, grep for every instance of its class across `src/` *and* `scripts/`, and treat `@deprecated` + `'use server'` as a red-flag pair. A finding is closed when the class is closed, not when the reported instance is.

### Context on the `/system` surface

`/system` was built as a **temporary staging-only superuser tool** pending a proper super/system-user design, and operational demand moved it into production ahead of that design. The findings above are therefore a scope mismatch rather than an oversight: a shared password guarding non-production data is a reasonable staging trade-off, and the same control guarding cross-tenant production data is not. It now carries real load with no alternative home, so [`09-PLATFORM-ADMIN-SPEC.md`](../rebuild/09-PLATFORM-ADMIN-SPEC.md) specifies the target design **and** an 8-step migration in which nothing goes dark, plus a §6 interim-hardening list that removes the sharpest edges in hours rather than weeks.

## Verified-good (do not regress)

Confirmed still correct during this pass:

- **The PHI gate itself** (`phiScanner.ts`) is well built: fail-closed on scan failure, a deterministic local pre-pass that blocks SSN/email/phone with **zero** network transmission, full-document chunking rather than a 15k truncation, and value-free findings (type + offsets + confidence, never the raw value).
- **`uploadDocument`** (`documents.ts`) blocks on both `hasPHI` and `scanFailed` *before* persisting, and is the only production writer of `DocumentVersion.content`.
- **`generateCourseAndQuizV46`** scans before creating the Job, so no scheduled work ever sees unscanned text.
- **The quiz-submit route** sends only question text, correct answers and options to Vertex — never the worker's own `selectedAnswer` values — and already had `guardApiSession`, Zod validation, enrollment-ownership and billing checks.
- Zero `console.*` outside `logger.ts`; logger used in 162 files.

### A transitive invariant worth writing down

`analyzeStoredDocument` is safe **only because** `uploadDocument` scans before writing `DocumentVersion.content`. The gate is transitive, not local. Any new code path that feeds document text into an AI call must either scan locally or read from a column with the same guarantee. This is the fragility that produced F-002 and F-082.

## How F-084 was fixed, and the reusable pattern

`generateArticleV46` and `generateQuizV46` became public endpoints purely by being exported from a `'use server'` module — one of them so a test could import it.

Adding `auth()` inside them was **not** an option: they run in background pipeline stages where no request session exists, so a session check would have broken generation outright.

The fix was to move the boundary rather than guard it. The six AI stages plus their private helpers now live in `src/lib/ai/course-pipeline-v46.ts`, a plain module with no `'use server'`. They remain freely exported and directly testable while ceasing to be action endpoints. `course-ai-v4.6.ts` retains only `generateCourseAndQuizV46` (which gates on `scanText`) and `checkCourseGenerationJobV46`, and drops from 1,236 lines to 674 — which also serves F-068.

Two things generalise from this:

1. **A `'use server'` module should contain only entry points.** If a function has no external caller, it does not belong there. The confirming signal here: the extracted module needs no `prisma`, no `auth`, and no request state, so the stage-C test dropped six mocks that existed only because the old module graph dragged them in. A boundary that simplifies its tests is a real boundary.
2. **Pin the action surface with a test.** `course-ai-v4.6.exports.test.ts` asserts the module exports exactly two functions and re-exports no stage. Verified non-vacuous by temporarily re-exporting `generateQuizV46` (both cases go red). This is the cheap, durable defence against the whole finding class — consider the same guard for any other `'use server'` module with a wide export surface.

Because this touched the primary course-generation pipeline, it was verified with `tsc`, the full suite, **and a production build** — server actions are wired at build time, so a type check alone would not catch a broken action manifest. A `qa-mafia` re-validation of the course-generation journey is still warranted before release.
